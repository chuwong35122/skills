# Tidy graph format — full reference

**You don't need this file to map.** `map.md` carries the working schema (a full example plus the length limits), and `scripts/tidy_graph.py check` enforces the rest and tells you what's wrong. Read this only when a validator message isn't enough, or when the user asks how the rendered views behave. For per-language read/skip/grep/resolve/verify tables, read `languages.md` instead.

**The format is language-agnostic.** Nothing here knows about a syntax: a node is a path, a symbol is a public name, an edge is a dependency. One graph covers a fullstack repo, and features span its languages.

```
.tidy/
  graph.json        ← YOU WRITE THIS
  index.html        ← generated: interactive force-directed graph
  contexts.md       ← generated: index — feature pointers, shared, external, orphans, edges
  features/*.md     ← generated: per-feature caveman entries with uses / used by
  candidates.json   ← generated by `find`: raw mechanical leads, unreviewed
  findings.md       ← YOU WRITE THIS: candidates triaged, ranked, fixable
  stale.txt         ← written by the post-commit hook, consumed by incremental updates
```

**Derived automatically — never author these by hand:** reverse edges (`← used by`), degree, shared-module detection, entry points, orphans, external services, feature-level edges, file counts, and every diagram. That's the point of the JSON: the whole class of "forgot to update the back-reference" drift is gone.

## `graph.json` keys

### Top level

| Key | Required | Notes |
| --- | --- | --- |
| `repo` | yes | Repo name — titles the graph page. |
| `updated` | yes | `YYYY-MM-DD` of this scan. |
| `stack` | yes | One caveman line: languages, frameworks, datastore, auth. List every language in a polyglot repo — it's the one place a reader learns the repo is Go + React. |
| `features` | yes | Declared feature list. A node may only name a feature declared here. |
| `nodes` | yes | One per mapped file **and** per external service / datastore / job. |
| `edges` | yes | Directed, `from` depends on `to`. |

### `features[]`

| Key | Required | Notes |
| --- | --- | --- |
| `name` | yes | kebab-case, from the domain language — not the folder name. |
| `route` | no | Routes/screens this feature owns. |
| `rbac` | no | Who may reach it: `public`, `admin, agent`, `auth required`. |
| `libs` | no | Array of libraries this feature leans on. |

Declare a feature named `shared` for cross-cutting modules. It's rendered inline in the index rather than behind a pointer, because it's the reuse surface.

### `nodes[]`

| Key | Required | Notes |
| --- | --- | --- |
| `id` | yes | Repo-relative path for files; a short stable name for services (`stripe`, `postgres`). Unique. Use the granularity the language uses — a Go package directory or a C++ header+source pair is one node. Ids must not contain `:`, which separates a path from a symbol name in `find` output. |
| `caveman` | yes | 4–10 comma-separated tokens, lowercase, no trailing period. **Max 10 — the validator rejects more.** |
| `feature` | no | Must match a declared feature. Omit for external services and unowned files. |
| `kind` | no | `file` (default), `route`, `db`, `external`, `job`, `config`. Drives node shape. |
| `path` | no | Real source path when it differs from `id` — makes the node's "open" link work. |
| `symbols` | no | Exported functions/classes in this file. Required for `DUP`/`REUSE` detection. |

### `nodes[].symbols[]`

| Key | Required | Notes |
| --- | --- | --- |
| `name` | yes | The public identifier, verbatim — a qualified name (`Ns::fn`, `Mod.fun`) is fine. Unique within the node. |
| `caveman` | yes | 3–8 comma-separated tokens. **Max 8 — the validator rejects more.** |

Publicly visible symbols only — internal helpers aren't reusable, so they aren't duplicates worth reporting. What counts as public is per-language (`languages.md` §3); where a language has no visibility marker, take what a sibling file could plausibly call. Optional by design: an existing graph without `symbols` stays valid and builds fine, it just yields no `DUP`/`REUSE` candidates. Backfilling one feature at a time via `/tidy <feature>` is a normal way to adopt them on a large repo.

**Symbols do not get their own edges.** `edges[]` stays file-level — symbol-level edges double the graph's cost for very little extra answer.

### `edges[]`

| Key | Required | Notes |
| --- | --- | --- |
| `from` | yes | Node id that depends on the other. |
| `to` | yes | Node id being depended on. |
| `label` | no | Only when the relation isn't obvious: `on submit`, `rbac`, `webhook`. |

Record real dependencies — imports, HTTP calls between services, queue produce/consume, DI registrations, table access, constant references in languages without file-level imports. Both endpoints must exist in `nodes`, or the build reports the edge as broken. Self-loops are rejected.

## Building

From the skill folder:

```bash
python3 scripts/tidy_graph.py check --root /path/to/repo   # validate, write nothing
python3 scripts/tidy_graph.py build --root /path/to/repo   # write html + markdown
python3 scripts/tidy_graph.py find  --root /path/to/repo   # write candidates.json
```

`--root` defaults to the current directory. Standard library only — no pip install, no network, no CDN. `check` exits non-zero when the graph is malformed, so it fits a pre-commit or CI step.

The validator catches: duplicate ids, missing/overlong caveman lines (node and symbol), unknown `kind`, malformed or duplicate-named symbols, features that were never declared, edges pointing at nodes that don't exist, and self-loops. Fix what it reports and re-run — `build` proceeds anyway but warns.

## `.tidy/index.html` — the interactive graph

Self-contained: the graph data is embedded, the force simulation and rendering are inline vanilla JS on a canvas. Opens from disk with a double-click, no server, no dependencies.

| Interaction | Behavior |
| --- | --- |
| findings filter bar | One toggle per label (DUP/REUSE/MOVE/DEAD/GOD) with a live count. Additive — active flags OR together. Only rendered when `find` has run; a label with zero hits renders disabled, so "none found" is visibly distinct from "never looked" |
| findings badge | Small coloured square per flag, up-right of the node, with an assigned initial (D/R/M/**X**/G — DUP and DEAD collide on D) drawn on top so it survives greyscale and CVD |
| hover / click a node | Highlights it and its direct neighbors, dims everything else, draws arrowheads on its edges |
| click | Opens the detail panel: caveman line, feature, kind, source link, full uses / used-by lists (each clickable to walk the graph) |
| drag node | Moves and pins it; double-click toggles the pin |
| scroll / drag background | Zoom at cursor / pan |
| search | Matches path, caveman text, feature, and finding id (`DUP-01`); non-matches recede |
| feature chips & dropdown | Isolate one feature plus its immediate neighbors |
| Fit / Re-layout | Re-frame the view / re-run the simulation from scratch |
| Theme | Light ⇄ dark, both selected palettes rather than an inverted one |

Encoding:

- **Size** = number of connections. The hubs are visibly the hubs.
- **Shape** = `kind` — ● file, ◆ route/entry, ■ datastore, ⬢ external service, ▲ job/cron. Shape, not color, carries this distinction, so it survives any color vision and any print/greyscale rendering.
- **Double ring** = shared across 3+ features — the reuse candidates.
- **Color** = one accent hue by default. "Color by feature" switches to the fixed 8-slot categorical order (never cycled; a 9th feature falls to grey "other"). **Color is a grouping aid, not the identity channel** — every node carries a visible label, which is what keeps the view readable under color-vision deficiency. Only the first three slots clear the all-pairs separation gate, so nothing depends on hue alone.
- Labels are the **shortest unambiguous** path suffix, so six different `page.tsx` files read as `login/page.tsx`, `billing/page.tsx`, and so on.

## Generated markdown

Regenerated from `graph.json` on every build; edit the JSON, never these.

`.tidy/contexts.md` — header, `## FEATURES` (one pointer line per feature, with file count and metadata), `## FEATURE: shared` inline, `## EXTERNAL`, `## ORPHANS`, `## EDGES`.

`.tidy/features/<name>.md` — that feature's entries, entry points first, then by descending connection count:

```markdown
- `services/invoice.ts` — build invoice, prorate, pdf render, email send
  → uses: audit/log.ts, db/schema.ts, stripe, utils/format.ts
  ← used by: app/api/webhooks/stripe/route.ts, app/billing/page.tsx, jobs/nightly-sync.ts
```

These exist so an agent can **grep** the graph — `grep -l "<path>" .tidy/features/*.md` finds a file's owning feature for a few dozen tokens, which is cheaper than reading any file and cheaper still than parsing the JSON.

## `.tidy/candidates.json` — machine output of `find`

Regenerated on every `find`. **Never hand-edit it, and never fix straight from it** — it's unreviewed. Every entry has a stable `id` (`DUP-01`, `REUSE-02`, `MOVE-01`, `DEAD-03`, `GOD-01`), a `type`, and a `why` naming the rule that fired.

```json
{
  "counts": { "DUP": 3, "REUSE": 5, "MOVE": 2, "DEAD": 7, "GOD": 1 },
  "candidates": [
    { "id": "REUSE-01", "type": "reuse-miss",
      "a": "utils/format.ts:formatTHB", "b": "billing/fmt.ts:getFormatTHB",
      "a_caveman": "format number, currency THB, 2dp",
      "b_caveman": "format number, currency THB, 2dp",
      "canonical": "utils/format.ts", "copy": "billing/fmt.ts",
      "why": "same normalized name + caveman overlap 1.00", "blast_radius": 4 }
  ]
}
```

Thresholds live at the top of the script: `SIMILARITY` (0.6 Jaccard over caveman tokens), `SHARED_THRESHOLD` (3 features), `GOD_USES` (12), `GOD_SYMBOLS` (15). They are loose on purpose — a strict pass reports nothing, and the agent is the filter.

## `.tidy/stale.txt`

Written by the hook, consumed and emptied by `/tidy`. One repo-relative path per line, no header, duplicates allowed (dedupe when reading).

```
app/login/page.tsx
lib/auth.ts
utils/format.ts
```
